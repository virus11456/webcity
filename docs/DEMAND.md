# M1-14 動態需求

每次日結先結算人口與就業，再計算 R／C／I／O 四種需求，成長系統在同一 tick 起使用新值。新城市也使用同一套公式，簡單模式一開始就有 +10 加成。Worker 是唯一權威，鏡像、每日歷史和只讀 debug 統計使用既有 stats 訊息。

## 計算與範圍

所有常數沿用 `data/simulation.ts` 的 DEMAND 和 `data/config.ts` 的 GAME_MODES。一般空城需求 70／20／20／0，簡單模式 80／30／30／10。需求保留小數，在加模式加成後 clamp 到 0～100，再由成長系統換算每 tick 的嘗試次數。零需求不生成新建築，既有施工照常完工。

- R：開局人口紅利、空缺職位減失業人數、幸福度、稅率。
- C：人口對商業職位需求減現有商業總職位，另扣缺貨修正與稅率。
- I：人口與商業供應鏈的需求減工業總職位，另扣出口修正與稅率。
- O：教育程度至少 2 的可工作人口對辦公職位的需求減現有辦公總職位，另扣稅率。

只統計 active 建築；施工、荒廢和燒毀建築不提供容量。勞動人口來自 M1-13 的實際整數配額，不能拿總居民或全體受教育居民替代。商業與工業職位用總容量，住宅吸引力則用尚未填補的職缺。

拆除、完工和斷路等結構變化立即更新人口，但需求等下次日結才重算；暫停時需求不變。既有外掛日結系統若在需求之後寫入幸福度或稅率，次日計算才會反映；未來幸福度／財政系統接入時須維持明確排程。

## 尚未明訂部分的選擇

GDD 未定義不同密度稅率如何合成共用需求，本卡用 RL／RH 算術平均作 R 稅率，CL／CH 算術平均作 C 稅率；I／O 各自使用原稅率。儲存的小數稅率乘 100 後才套用每百分點 4 點懲罰。

商業缺貨以 active 商業建築 `problemTimers.noGoods > 0` 的棟數比例計算。貨物流動尚未實作，正常遊戲該比例為零；出口資料尚不存在，工業出口修正暫用零。純公式已提供 0～1 的出口受阻比例入口，可供 M2 接入與測試；不憑空製造堵塞或物流狀態。

此卡不加入需求 HUD（M1-20）或 setTax 指令／財政介面（後續財政任務）。正常遊戲稅率仍為 9%，稅率效果以權威狀態與純公式測試驗證。無新增 runtime 依賴。

## 驗證

單元測試覆蓋空城與簡單模式、工作過剩／失業、早期紅利、四種稅率方向與百分比換算、幸福度、商業／工業／辦公公式、缺貨出口修正、最終 clamp、active 篩選、人口日結順序、鏡像／歷史一致與暫停。成長整合測試驗證零需求停止新建築、職位移除後恢復。

既有人口 Playwright 流程增加 RCIO 斷言：初始值、商業過剩後 C 降低、R 因職缺上升、拆除商業區後次日日結 C 回升且 R 下降。使用原生滑鼠／觸控，涵蓋 iPhone、iPad、桌機；未新增 UI。

本次結果：lint、typecheck、590 項單元測試及正式 build 通過；完整三裝置 E2E 70 通過、11 個裝置不適用略過（3.6 分鐘）。
