# M2-16 消防與火災

Worker 每日以城市 seed、建築 ID、日期產生可重現亂數，依 GDD `0.0002 × (1 - fireCoverage)` 決定活躍建築是否起火。起火當天損毀為 0；之後每天增加 0.5，兩天仍未撲滅則成為 burned，立即重算人口、電水和服務。日結有 lastDay 保護，暫停與重算不推進火勢。

FireSystem 優先選道路網路距離最近且仍有車輛容量的消防局／總局，再驗證有向車道可通行；消防車共用 TrafficSystem 的跟車、路口與斷路處理。實際抵達火場的事件才撲滅，不以覆蓋率、路徑存在或畫面距離判斷。消防車數取原表 5／15 台乘預算後向下取整；進行中的出勤保留至完成，停用／拆除／消防局自身起火則取消任務。火場可在風險覆蓋半徑外，仍會嘗試派車。一次同時最多 128 筆救援、每 tick 最多 8 次車道路徑請求，失敗每 2 ticks 重試，優先處理既有任務，再輪流處理新火場。

斷路車輛停留實際位置，修復後從該位置恢復路徑；火勢持續，不會讀檔後重新從消防局出發。到場即完成救援並移除該車輛，本卡沒有額外模擬返回車庫行程。交通行走與市民生活日沿用 M2-10 的時間尺度；火災使用財政日（×1 每天 2.4 秒），沒有另行延長救援期限。

Building.fire 保存 burning、damage、startedDay；WorldSnapshot.fire 保存 lastDay 與出勤任務。消防與貨運共用唯一 mission ID，但用 purpose 7／6 區分，並各自取出屬於自己的到達事件。讀檔驗證任務唯一性、目標仍起火、來源消防局有效、車流目的地一致、損毀和時間範圍。缺少 fire 集合的既有 v1 檔補空集合，既有資料不變，沿用 M2-13 的相容擴充方式。

畫面使用單批次 Instanced Billboard，程序火焰與黑煙無外部素材，每幀重用 attributes；最多 512 個、超過 1500 m 不繪製。燃燒與燒毀分區建築染黑，警消醫教設施亦染黑。檢視顯示消防車派遣局／目的地／救援用途，建築顯示火災狀態與損毀百分比。

驗證涵蓋實際抵達、無消防局兩天燒毀、日結不重複、車數預算、最近連通消防局、斷路與原地修復、讀檔續行、非法存檔、消防與貨運共存、Worker 人口連動，以及火焰批次增刪。原財政黃金情境的固定 seed 現在有一棟住宅燒毀，因此預期人口 817、收入 701.28、支出 389.28，新增燒毀數量斷言，第四週獲利與水電驗收保持不變。
