# M1 MVP 整合

## 初始對外道路

新遊戲的 `starterRoads` 由主選單傳到 Worker，Worker 一次生成兩條反向高速公路、四個地圖邊界端點與進出匝道。初始工程免費，已購起始地塊內的路段照道路表收維護費；地塊外標記 `regional` 的路段由區域維護，不佔市府預算。道路下方使用既有路基工程降低切穿地形問題。位置、高度集中於 `data/starterCity.ts`。

M1 使用可連接的同平面出入口；立體交流道、完整車道與車輛尋路留給 M2。道路資料是正式世界的一部分，可檢查、接路、存讀檔；不是展示物件。初始高速公路不可分區。自動水管只處理已購地內的道路，不沿城外區域道路鋪設。舊存檔與開發空白城市入口不補插任何道路。

## 完整流程

`integration.spec.ts` 從主選單建立一般模式河谷城市，在正式預鋪匝道接出街區，使用滑鼠／模擬觸控鋪路、分區、放風力機／水塔／排水口、接水管與配電，播放真實 Worker 模擬直到人口超過 200，暫停後存檔、重新整理、從主選單繼續，逐項比較人口、資金、建築及分區。沒有向 Worker 注入人口或跳過建設指令。

`performance.spec.ts` 使用真實 Simulation 建設指令及自然成長／移入，生成 5,162 人口、129 棟建築的可讀存檔。此效能 fixture 使用受控平坦地形與沙盒，不是一般模式的玩法平衡證明。透過 IndexedDB 寫入 fixture 後從正式主選單讀檔，開啟模擬 ×1，暖機兩秒後量測五秒 requestAnimationFrame。低畫質，Desktop 1440×900／iPhone 393×852／iPad 834×1194，桌機 60Hz 以 ≥58 FPS 容許 3% 排程誤差，行動 viewport ≥30 FPS。這些是同一台主機的 Chromium viewport 模擬，不能等同實際 iPhone 的 GPU／Safari 表現。

驗收截圖在 `screenshots/m1-26/`，操作 GIF 由測試錄影產生。完整測試結果記錄於 `TASKS.md`。

## 範圍

M1 完成可存檔的城市建造循環。個別市民、動態通勤、車流、進出貨與警消垃圾等服務不以裝飾車輛或統計數字冒充完成，仍按 M2 及後續任務卡實作。音效與里程碑系統依原任務編排保留。

CI 的無 GPU 虛擬機略過 FPS 門檻案例；一般功能、完整新城市／存讀檔與三裝置互動照常執行。FPS 另在具 GPU 的本機 Chromium 驗證。既有 CI 時間預算延長至 30 分鐘，以容納新增流程與錄影，不刪減功能回歸。

## 最終驗證紀錄（2026-10-10）

Chrome 154.0.8037.98，本機 GPU、低畫質、模擬 ×1。三個 viewport 皆為 5,162 人口、129 棟；5 秒取樣各 301 幀，平均約 60.00 FPS，p95 約 16.7–16.8 ms。完整建城案例人口為 282，水電污水缺口均為 0。

694 項單元測試、lint、typecheck、build 通過。全回歸 111 通過、11 略過；唯一失敗為平板比較資料時未等 Worker 的暫停回覆，造成一次完工更新的取樣差異。測試改為等 `data-speed=0` 後再捕捉城市資料，三裝置整合與存讀檔 6 項補驗通過，合計驗證 112 個不重複 E2E 案例。GIF 是通過的桌機流程錄影，縮為 320×200、1 FPS 以控制 repository 大小；原始影片由 E2E artifact 保存。
