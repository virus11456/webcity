# M1-07 沿路分區格

本卡建立分區資料與 Worker 同步，沒有新增格線、塗抹按鈕或建築成長；這些分別由 M1-08、M1-10～M1-12 接續。

## 座標與資料

- `world/zoneGrid.ts` 的 `rebuildZoneGrid(world)` 是純函式，回傳新 `blocks`、已移除 ID、更新 `zoneBlockIds` 的道路及全域 `nextId`，不修改輸入。
- 每格 8×8 m，道路兩側各四格深，從道路完整寬度外緣開始；不足 8 m 的尾端不產生殘格。
- `origin` 是第一格臨路邊的中心，`dir` 是沿路單位向量。`side=+1` 朝 `(-dir.z, dir.x)`，另一側取反。
- 陣列使用 `depth * width + column`；`zoneCellCenter`、`zoneCellPolygon` 是渲染、選取和未來工具的共用座標介面。
- 直線每側一個多欄 block；曲線依弧長分成一欄 block，各自對齊局部方向。密集彎道會保守裁掉相交格子。
- 地面碎石路可產生格子；高速公路、匝道、高架不產生可分區格。道路表的 `low-density` 等分區限制留給 M1-08 的塗抹驗證。

## 裁切與優先權

整格判定，不只檢查中心：

1. 超過地圖邊界、水面接觸／水域、地形三角面坡度大於 25% 的格子標 `255`。
2. 地形檢查裁切相交三角形，計算三角平面梯度長度及裁切多邊形最低高度，所以格子內的小水窪不會漏判。
3. 道路完整寬度、端點封口與路口圓角的保守範圍，以及其他建築占地，會裁掉相交格子。邊界相切可保留，正面積重疊才衝突。已記錄於 `buildingAt` 的自身建築不算另一個障礙物。
4. 合法候選格按 `createdOrder`、block ID 排序，先建立者保留；使用空間索引縮小候選，再做旋轉多邊形面積檢查。

`ZoneBlock.createdOrder?: Id` 記錄最早來源 block 的 ID；未帶此欄位時以 block ID 為準。新增路口把直線道路切成新路段時，子段繼承原先的 8 m 格線相位及建立順序。仍位於同一世界位置／方向且合法的格子保留分區碼及 `buildingAt`。被道路或水域等裁掉的格子清空占用，不暗中保留失效分區。

刪路後重新呼叫同一個函式，會移除原路段 blocks，重新驗證其他格子並釋放重疊優先權。拆除 UI 與 Worker 拆除命令仍屬 M1-09，這裡提供其必要的資料重建功能。

## Worker 整合

成功鋪路的順序：驗證 → 更新道路圖與扣款 → 整平地形 → 重建分區格 → `roadsChanged` → `zonesChanged` → `fundsChanged`。

- 道路與格子共用全域 ID 計數器。
- `roadsChanged.added` 含已更新的 `zoneBlockIds`。
- `zonesChanged` 同步所有當前 blocks 及移除清單；鏡像更新 `nextId`，工具刷新快取。
- `WorldMirror.readZoneBlocks()` 只複製分區格，呼叫端修改結果不會污染鏡像。
- `?debug=1` 下 `window.__webcityZoneStats()` 提供 block、合法格及無效格數量，供瀏覽器驗收使用。

目前採路網變更時完整重建，使用空間索引避免所有格子互相比對；沒有在每幀重算。大量路網的局部增量重建屬後續效能優化。建築本體的反向 `zoneBlock`／`blockCell` 關聯及拆遷處理，需在 M1-12／M1-09 整合；本階段城市尚無模擬建築。格子計算不授予土地擁有權，未來塗抹指令仍需驗證 `ownedTiles`。

## 驗證

14 項新單元測試涵蓋兩側四格、剩餘長度、旋轉、平行路優先權、路口裁切、道路種類、高架、曲線、刪路、非 8 m 切段後連續重建、建築占地、地圖邊界、小水窪與 25% 坡度。Worker 測試另檢查事件順序、全域 ID、道路所屬 blocks、鏡像一致與防禦性複製。
