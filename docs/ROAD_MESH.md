# M1-06 道路 Mesh

## 已接上的操作

「開始鋪路」建造的真實道路現在有柏油車道、抬高人行道、路緣立面、中央白色虛線與路口停止線。四線道以上使用黃色雙線；同向車道使用 3 m 實／6 m 空的白色虛線。碎石路與高速道路不生成人行道。這些規則適用於道路資料；未解鎖的道路仍遵守原有里程碑。

`render/roads/geometry.ts` 以曲線弧長取樣後擠出橫斷面。路段在共用入口截面停止，路口依排序後的相接道路寬度填補中央多邊形及圓角人行道；死巷使用半圓封口。標線在入口前停止，避免穿越路口。路面、人行道和標線使用不同高度，避免共平面閃爍。

## 地形與 Worker

Worker 建造成功後，以 `world/roadBed.ts` 計算稀疏地形整平資料，與 `roadsChanged.terrain` 一起送出。鏡像先套用地形，再通知工具與渲染。渲染器同步地形幾何、地形選取與水面深度貼圖；主執行緒不修改權威世界。

地面道路的縱向坡度由端點高度插值，横向整平。16 m 高度圖會整平到支撐路面邊緣的鄰近三角形，因此整平區域比路面略寬。高架路段不改變地形。既有道路接點依路面高度連接，不再以施工後較低的路基地形判斷是否為地面節點。

## 合批與生命週期

- CPU 快取每個路段／路口片段，路網改變才重算。
- 片段依中點所在的地形 Chunk 歸屬，再把相鄰 Chunk 放入至多 24 個 GPU 批次。跨 Chunk 長路段不裁切；批次包圍球涵蓋全部幾何。
- 共用頂點色材質，不為人行道或標線增加 material group。
- 重建分幀處理，目標每片段工作時段 4 ms；單一幾何建立或 GPU buffer 完成可能超出時段。最後完整交換新批次，避免路口與路段更新一半。
- 未改變的 GPU buffer 保留；取消重建、移除道路與 dispose 會釋放資源。

## 驗證

- Vitest：交叉／T 字／30°／45° 路口入口與路段共用頂點、有限座標及面方向、曲線與坡度、稀疏地形更新冪等性、高架排除、1,000 路段合批、快取重用、取消重建。
- Worker 回歸包含整平後繼續接路、路口拓樸與鏡像高度一致。
- `npm run dev` 後執行 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=... node scripts/verifyRoadMeshes.mjs`，以真實 WebGL 渲染 1,000 路段並檢查 `renderer.info.render.calls < 30`，另輸出四種路口截圖。
- 本機 Chrome 實測 1,000 路段為 **18 draw calls**，兩次量測跨 38～42 次重建時段完成；最長單次時段約 5.6～8.5 ms。這是道路獨立場景的結果，不是含地形、水與展示建築的全場景呼叫數，亦非手機實機效能承諾。

## 範圍

本卡完成 MVP 道路外觀；林蔭樹木、路燈、交通號誌、斑馬線及橋墩細節留待後續道路／美術任務。曲線幾何可生成，但曲線建造工具仍待 M2。極短而密集的寬路交會需要後續路口叢集處理；目前以路段長度限制圓角截距。

尚未完成存檔、沿路分區、建築成長、居民與車流。展示街區仍是獨立展示資產，不代表這些模擬已完成。
